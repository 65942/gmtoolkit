# GMToolKit (`gmtoolkit`)

Cross-platform (Windows/Linux/macOS) Rust tool that sets up Garry's Mod: game content via steamcmd, VPhysics, GModPatchTool, x86-64 (Chromium) branch switch, and compatibility tool (Proton) choice on Linux.

## Commands
- `cargo run` (no args) — GUI (egui, `src/gui.rs`); each button re-runs this binary with CLI args in the background and streams stdout/stderr into the log
- `cargo test` — unit tests (inline `#[test]` in src/main.rs and src/gui.rs)
- `cargo test -- --include-ignored` — also hits this machine's real Steam files, steamcmd and GitHub
- `cargo run -- <game id> [off]` — install / uninstall content; ids are in `GAMES` (cstrike, tf, dod, hl2mp, left4dead2, …). Downloads GBs and edits the real GMod install
- `cargo run -- sync` — run `sync_steam_copies` (mount path fixes, Steam-copy cleanup, model lists, addon)
- `cargo run -- vphysics [off|<tag>]` / `jolt [off|<tag>]` / `chromium [off|<tag>]` — a release tag installs that version instead of the latest
- `vphysics` (Box3D) / `jolt` install over every existing `bin/**/vphysics.{dll,so}` with `.orig` backups shared by both: installing one first restores stock (`restore_vphysics`, also deletes Jolt's `vphysics_jolt_*` per-CPU builds), so they replace each other; `off` restores. The GUI asks before installing one over the other
- `cargo run -- chromium` — "Chromium patches": refuses unless `MountedConfig` BetaKey is `x86-64`; runs latest GModPatchTool headless (`FORCE_GUI=0`, `-s`), log relayed as `[patch]` lines, tag + patched files with mtimes saved to `<data>/versions/chromium` (badge = all unchanged)
- `cargo run -- skategm [<tag>] [<disc .iso|default.xex>] [--skate2 <disc>] [--keep-data] [--no-addon] [--maps all|none|<map,...>]` / `skategm off [--delete-data]` — `--skate2` (remembered in `disc_skate2.txt`) is only for `sgm_skate2_*` maps; the flags are their installer window's checkboxes (keep converted data, install add-on, which maps; `SKATEGM_KEEP`/`SKATEGM_ADDON`/`SKATEGM_MAPS` to `skategm.py`; CLI default: add-on + all maps). The GUI asks them in a dialog (`SkateOpts`, with Skate 3 / Skate 2 disc fields + Browse, prefilled from `skategm_discs`) on Install/Update, and on Modify when up to date: add-on defaults on unless the Workshop item (`SKATEGM_WORKSHOP`) is subscribed, maps off; the map list is `SKATEGM_MAPS` (copied from 9.0, `--maps all` when every box is ticked). Without the add-on, `addons/skategm` is removed so it doesn't clash with the Workshop copy. refuses unless `MountedConfig` BetaKey is `x86-64`, and unless Windows or GMod under Proton (`skategm_supported`; the module is win64-only). Downloads the release zip, uv (`UV_TAG`) and vgmstream (`VGMSTREAM_TAG`) into `<data>/skategm`, then `uv run` (Python 3.13 + numpy, pillow, soundfile) `src/skategm.py`, which converts the disc with the zip's `exporter/convert.py` and copies the module, add-on, HUD, sounds and music like SkateGM's own installer, then builds the maps (`mapgen.install_maps` → `addons/skategm_maps`, Skate 3 only; already-built ones skipped). Conversion is skipped when `<data>/skategm/data/converted.txt` matches tag + disc; decoded districts/disc files in `data/mapgen` are kept for retries. `datapath.txt` gets `mount_path` (Z: under Proton). The disc is remembered in `disc.txt`, so Update re-converts from it. `off` removes SkateGM's files and the downloads in `<data>/skategm`, but keeps `data/skategm` (settings, boards, replays) and, unless `--delete-data` (a checkbox in the GUI's uninstall dialog), `<data>/skategm/data` (converted data, map cache) and the remembered discs.
- `cargo run -- gwater2 [<tag>]` / `gwater2 off` — GWater2 (`meetric1/gwater2`, only `GWATER2_TAG` offered; its Windows zip is pinned in `PINNED`). Unpacks the release zip into the GMod folder like its `.bat` installer: Windows zip on Windows/Proton; natively on Linux the `_LINUX` zip, refuses unless MountedConfig BetaKey is `x86-64` and `libcuda()` finds the NVIDIA driver, then copies libcuda to `bin/linux64/libcuda.so`. Files listed after the tag in `<data>/versions/gwater2`; reinstall/`off` delete them. Its Lua is Workshop-only (`GWATER2_WORKSHOP`): the Steam page is opened if `<library>/steamapps/workshop/content/4000/<id>` is missing. Hidden on macOS
- `cargo run -- chromium off` — opens `steam://validate/4000` (Steam must be running; also reverts Box3D)
- `cargo run -- switch <x86-64|default|prerelease|dev> [native|proton|<compat tool id>]` — branch (+ compat tool on Linux); refuses while Steam runs.
- Windows build from Linux: `PATH=$HOME/.cargo/bin:$PATH cargo xwin build --release --target x86_64-pc-windows-msvc` (user-local rustup + cargo-xwin; system rust has no Windows target)

## How it works
- steamcmd is downloaded on first run into `dirs::data_dir()/gmtoolkit/steamcmd` (unpacked with the system `tar` on Linux/macOS); content downloads anonymously via dedicated-server app IDs listed in `GAMES` (id = main content folder = mount.cfg entry name). Not possible anonymously: Alien Swarm (635 needs a subscription), Nuclear Dawn (server has no content), Contagion (no server app), Portal/Portal 2/HL2 episodes (no server).
- Content folders are detected after download by `content_folders` (top-level dirs with `*_dir.vpk` or maps/materials/models/sound, skipping bin/platform/hl2), so DLC/update folders (L4D2) get their own mount entries (`mount_name`); `remount` replaces all of a game's entries at once.
- Game content is mounted via `garrysmod/cfg/mount.cfg` (`remount`/`with_mount`: commented examples and CRLF preserved). Games the user owns on Steam (`Game.steam_appid`) get no mount.cfg entry: GMod mounts those itself with their own path ID; `remove_game` drops our copy. `sync_steam_copies` (GUI start, after tasks, `switch`, `cargo run -- sync`) does that cleanup automatically.
- mount.cfg content only gets GMod's shared `GAME` path ID (verified in-game with `path`), so Lua can't list a game's files. The app writes each game's model list to `garrysmod/data/gmtoolkit/<id>.txt` (`write_index`: first line name, then `models/....mdl` from VPKs + loose) and installs `src/gmtoolkit.lua` as `addons/gmtoolkit/lua/autorun/client/` while any list exists (`sync_addon`). The addon adds each game under the spawn menu's Browse → Games folder (found a frame after PopulateContent; own "GMToolKit" folder as fallback; icons created on click) shows a hint when a listed game is also mounted natively, and overrides `IsMounted` to return true for app-installed games so GMod's own `needsapp` spawnlists (settings/spawnlist: CS:S, DoD:S, TF2, L4D, CS:GO, …) appear. Maps-only games (CS:S) get a name-only list file for that. Games without a built-in list get one generated at `PopulatePropMenu` via `spawnmenu.AddPropCategory` (no files; IDs from 770000): a parent per game, a sub-list per top-level model folder, junk filtered by `useful()`.
- Under Proton (GMod has a compat tool forced) mount.cfg paths must be Wine paths, `Z:/home/...`; `mount_path`/`host_path` convert, and `sync_steam_copies` (also run by `switch` and `cargo run -- sync`) rewrites entries when the style is wrong.
- Otherwise the dedicated server is downloaded to `<GarrysMod>/gmtoolkit/<id>` (`content_dir`: same drive as GMod, visible to Flatpak/Snap Steam and Proton) and `prune` deletes everything GMod doesn't use: keeps `<folder>/*.vpk` (except CSS) and `maps/*.bsp|nav`, materials, models, sound, particles; keeps `steamapps/` for steamcmd. CSS keeps only maps (GMod ships CSS content).
- steamcmd tries the Windows depot first (`+@sSteamCmdForcePlatformType windows`; DoD:S's Linux depot fails with "Missing configuration"), then Linux (some servers only ship content there).
- GMod folder: `gmod_dir()` uses the folder saved in `<data>/gmod_path.txt` (first-launch screen / Settings tab, `save_gmod_dir`), else `detect_gmod_dir()`. GMod's manifest is derived from it (`<library>/steamapps/appmanifest_4000.acf`). Browse uses `rfd` (xdg-portal on Linux) on a background thread.
- Steam is found by `steam()`: checks native, Flatpak, Snap and Debian install paths and prefers the one that has GMod (steamlocate alone returns only the first install). Library folders on other drives come from that install's libraryfolders.vdf. Always use `steam()`, never `SteamDir::locate()` directly.

## Decisions
- Compat tools listed by `compat_tools()`: Proton Experimental always first/recommended (Steam fetches it on demand), Valve Protons from library `common/Proton *` (id via `valve_proton_id`), custom ones from `compatibilitytools.d` manifests.
- GUI theme: on Linux `watch_desktop_theme` re-checks every 3s: KDE's full color scheme from kdeglobals (`kde_palette`), else the XDG settings portal via `busctl` (`portal_theme`: dark/light + accent); elsewhere egui's OS detection. Colors in `pal()` / `style()`, accent in the `ACCENT` atomic.
- Versions: installs record a version in `<data>/versions/<id>` (GitHub tag, or the server's Steam buildid from its appmanifest). The GUI fetches latest GitHub releases (`releases`) and current server builds (`latest_builds`, one anonymous steamcmd app_info_print) in the background and shows "Update available"; GitHub items also get a version dropdown. Installs from before tracking show "version unknown".
- GUI fonts/shapes follow the desktop: `desktop_font` (KDE kdeglobals `font=`/`fixed=` or Plasma defaults Noto Sans/Hack 10pt; else gsettings; Windows Segoe UI/Consolas; macOS SF) → `font_file` (fc-match on Linux) → `load_system_fonts`; all text sizes scale from `base_px()`. Corner radii per desktop in `radii()` (Breeze small, Adwaita round, Win11/macOS between).
- Features a platform can't use are hidden, not disabled: compat tool dropdown Linux-only, VPhysics rows (notes, release fetch) not on macOS.
- Cancel/Resume: tasks run in their own process group (Unix) and Cancel kills the group (`kill -TERM -<pgid>`) or tree (`taskkill /T`); closing the window cancels too (`on_exit`). A game dir with no mount entry is `is_partial` → row shows Resume (re-runs the install; steamcmd continues the partial download) and Discard (`<id> off`).
- GUI layout: first launch asks for the GMod folder; tabs "Game content" ("Supported by GMod" / "Other Source games") / "Patches" (version card + Chromium + Box3D) / "Settings" (GMod folder). `item_row` buttons sit in a fixed-width column: Install; Update/Switch + Uninstall when installed; disabled "Steam" for owned games; Resume/Discard for partial downloads; Cancel + spinner while running. Bottom status bar shows the last log line with a Show log toggle.
- Compat dropdown shows GMod's actual forced tool; a third-party one (e.g. Proton-GE) is left untouched unless the user picks Native / Proton Experimental.
- VPhysics: Box3D (active) and Jolt (`misyltoad/VPhysics-Jolt`, last release 0.20 in 2024). Jolt's assets have no GitHub digest, so their sha256 is pinned in `PINNED` and only `JOLT_TAG` is offered. Neither has a macOS build.
- x86-64 branch on macOS is unconfirmed; mark experimental.
- Branch switch: `BetaKey` in `appmanifest_4000.acf` UserConfig; compat tool: `CompatToolMapping` 4000 → tool id in `config/config.vdf` (removed for native). Steam must be closed.
- Steam VDF: parsed with `keyvalues-parser`, but written by our own `write_vdf` — Steam escapes only `\\` and `"` and keeps newlines literal, which neither of the crate's renderers matches.
- GitHub downloads (`github_asset`) are verified against the release asset's `digest` (sha256) from the API.
- Proton installs of GMod use the Windows dlls on Linux, so vphysics swaps whichever files exist rather than guessing by OS.
- macOS GModPatchTool ships as a .dmg inside the zip; mount/run path is untested.
- SkateGM: their Setup.exe isn't used. It's a PyInstaller onefile build and fails under every Wine (Wine's `_wtempnam` truncates the `_MEI<pid>` prefix, so PyInstaller's check fails with a modal error), so the same uv route runs on Windows too. Without their `aems_render.exe` only the foot-brake sound loops are missing. Verified in-game under GE-Proton, controller included
- SkateGM maps: Source's compilers (vbsp/vvis/vrad/studiomdl/bspzip) are Windows exes, so under Proton `skategm.py` shims `mapgen.sourcetools.subprocess` to run them with GMod's Proton wine (`proton_wine`, `SKATEGM_WINE`) in its own prefix `<data>/skategm/wine` (Proton kills everything in GMod's prefix when GMod closes), paths as `Z:`. Spawn start method (their nested process pools deadlock under fork). Their `vtfenc.dll` texture encoder is required (identical maps across PCs) and ships only inside Setup.exe: `src/vtfenc.rs` is a verbatim copy (keep it byte-identical), `build.rs` builds it as a cdylib for x86_64 Windows/Linux targets (passes `RUSTC_LINKER` + `CARGO_ENCODED_RUSTFLAGS`, so cargo-xwin works) and sets `cfg(vtfenc)`; main.rs embeds it with `global_asm!` `.incbin` (`vtfenc()`), since as an `include_bytes` constant it made LLVM crash (GlobalDCE SIGSEGV) on ~half of the Windows release builds; `install_skategm` writes it as `native/vtfenc.dll` only when the release's `vtfenc.rs` equals ours, else `skategm.py` builds it with the user's `rustc` (no `+crt-static` off Windows: it drops cdylibs on linux-gnu); neither → maps skipped. Its one `powf(2.2)` (feeds only the VTF header's f32 reflectivity) differs per libm: their Setup.exe vtfenc.dll is a `windows-gnu` build with MinGW's pow, off by up to 4 ULP from glibc/ucrt on 100/256 inputs. `build.rs` patches the call to a `SETUP_POW` table dumped from that DLL (calling its unstripped `pow` under Wine), so ours encode exactly like Setup.exe; drop it once upstream replaces the powf. The rustc fallback stays unpatched. sgm_skate3_maloof verified in-game under GE-Proton
- GModPatchTool: run its release headless; not reimplemented (~2k lines of binary patching + server-hosted patch files that track GMod updates).
- Releases (`.github/workflows/release.yml`): portable static-CRT `.exe`, `.AppImage` built on Ubuntu 22.04, universal macOS binary zipped.
- Keep it minimal: single binary; GUI drives the CLI by spawning itself, so features are written once as CLI commands.
- Windows builds use `windows_subsystem = "windows"`; every spawned console child goes through `hide_window` (CREATE_NO_WINDOW).
